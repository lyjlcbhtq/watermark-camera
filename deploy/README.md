# 国内部署与车况留证使用

这一目录提供可部署配置，**没有替你购买域名、部署服务器或开通存证服务**。当前实现适合把代驾接车前、交车后的水印录像与本机校验记录保留下来；它不是滴滴官方认证工具，也没有可信时间戳或第三方存证资质。

## 推荐路线：国内 HTTPS 域名 + Node 服务 + Nginx

同一个域名提供页面、定位地址接口、校验 Worker 和校验页，减少跨域故障。录像和文件校验在手机上完成，此服务**不接收或存储视频**。地址查询会把坐标发送给部署服务器与高德；服务器只做短期内存缓存。

准备条件：

- 用户自己控制的域名和可用 HTTPS 证书。
- 国内服务器及与域名、接入商匹配的备案等手续；实际要求以接入商和当地规则为准。
- Node.js 22 或更新的受支持 LTS、Nginx、systemd。
- 如需中文地址，准备高德「Web 服务」Key，并按高德控制台要求配置服务端 IP 等限制。Key 只放在服务器环境文件中；未配置时仍保留设备坐标，接口返回 503。

本机验证可以直接从项目目录执行，无需构建或安装运行时 npm 依赖：

```sh
node server.mjs
```

访问 `http://127.0.0.1:8080/`。手机访问远程地址必须使用 HTTPS，不能把局域网 HTTP 测试当作生产方案。

生产部署步骤：

1. 将完整发布包放入 `/opt/watermark-camera/releases/<版本>/`。创建只读的 `watermark-camera` 服务账户，确保该账户可以读取发布目录；程序没有写入服务器磁盘的需求。
2. 将 `/opt/watermark-camera/current` 指向选定发布目录。上传完成、检查文件齐全后再切换链接，不要逐个覆盖在线目录中的 `index.html` 和脚本。
3. 复制 `camera.env.example` 到 `/etc/watermark-camera.env`，由 root 管理并设为 `0600`。填写服务端 Key。根路径使用 `CAMERA_BASE_PATH=/`；需要子路径时使用 `/watermark-camera/`，保留前后斜杠。
4. 复制 `watermark-camera.service` 到 `/etc/systemd/system/`。确认实际 Node 路径与模板的 `/usr/bin/node` 一致，然后执行 `systemctl daemon-reload`、`systemctl enable --now watermark-camera`。
5. 将 `nginx.conf.example` 复制到 Nginx 的 `http` 配置目录，替换域名与证书路径。执行 `nginx -t` 后 reload。只对外开放需要的 80/443 端口；Node 默认只监听 `127.0.0.1:8080`。
6. 用 iPhone Safari 打开 HTTPS 地址，允许相机、麦克风和精确定位，确认拍摄、保存和校验功能，再添加到主屏幕。首次离线使用之前必须在线成功加载并安装缓存。

`CAMERA_TRUST_PROXY=1` 只适用于此类回环地址反向代理。Nginx 模板会覆盖客户端传入的 IP 请求头；如果在它前面再加 CDN，需只信任 CDN 公布且维护的出口 IP，正确配置 Nginx 的真实 IP 处理。不要直接信任任意 `X-Forwarded-For`，也不要为了绕过限流关闭所有限制。

更新时上传完整新目录、切换 `current` 并重启 `watermark-camera`。服务使用文件 ETag 与 gzip；`index.html`、`sw.js` 不使用长期 HTTP 缓存。浏览器的新 Service Worker 在完整缓存新资源后等待旧窗口关闭再启用，避免打断正在录制的页面。代码变化应同时递增 `sw.js` 缓存版本。

## 可选路线：国内对象存储 + CDN

适合已有静态托管资源的情况。使用同一套 HTTPS 域名和完整发布资源，**不要把仓库根目录整个公开**。只导出公开文件到一个空目录：

```sh
node deploy/export-public.mjs /tmp/watermark-camera-public
```

上传该目录内的文件，保留 `icons/`、`vendor/noble-hashes/` 等子目录。配置 `.js` 为 JavaScript MIME 类型，`.html` 为 HTML，禁止目录索引。目录默认首页设为 `index.html`，不要把缺失的 JS 文件也重写成首页；错误文件必须返回 404。

- `index.html`、`sw.js`：`Cache-Control: no-cache`。
- 其余目前未带内容哈希的文件：`Cache-Control: public, max-age=0, must-revalidate`，允许 ETag 与 gzip。不要给这些可变文件套一年缓存。
- `<应用路径>api/reverse-geocode`：路由到 Node 服务源站，保留请求路径与参数，禁用 CDN 缓存和坐标查询日志。该接口需要和页面同源，才能沿用当前 CSP 与客户端逻辑。
- 若暂不提供地址接口，页面仍可使用设备坐标；不要用假的地址响应掩盖缺失配置。

国内域名、备案、CDN 的覆盖与计费条件由所选服务商决定。境外托管可以作为人工备用入口，但换域名会改变浏览器存储作用域，不能自动读取主域名里尚未另存的录像。更换域名前先导出重要文件。

## 地址接口约定与资源边界

`GET <CAMERA_BASE_PATH>api/reverse-geocode?longitude=<经度>&latitude=<纬度>`

接口接收高德所需的 GCJ-02 坐标；应用在中国境内从设备 WGS-84 坐标转换，原始设备坐标仍应独立保留在采集记录中。地址是地图服务的近似描述，不是定位真实性认证。

成功返回 `{ "status": "1", "regeocode": { ... } }`。未配置 Key 返回 503，参数非法返回 400，上游失败返回 502，超时返回 504，请求过多返回 429。返回错误不会包含上游 URL、Key 或供应商调试信息。

当前默认边界：5 秒上游超时、最多 4 个并发上游请求、同坐标合并并发、2 分钟内存地址缓存且最多 512 条、每来源每分钟 30 次及全局每分钟 120 次。API 响应使用 `no-store`，不做视频上传；增大用户规模前应按实际请求量配置容量与配额。

Nginx 样例的普通访问日志不含查询参数，定位接口关闭访问日志及请求错误日志，减少坐标落盘。部署的云负载均衡、CDN、监控平台仍可能另记日志，需要在这些服务上同步设置。不要在诊断输出里打印真实环境变量或 Key。

## 上线验收与使用边界

上线前用真实域名分别测试移动、联通、电信，以及经常接单的网络环境。记录首次打开、缓存后打开、相机就绪耗时；检查 DNS、TLS、文件响应和接口失败率。云端或境外机器测得的延迟不能代表国内三网效果，本项目也不能保证所有地点随时有网。

在 iPhone 上至少验证：在线首次安装、主屏幕重开、离线重开、录制与保存、麦克风拒绝后的无声提示、精确定位关闭/室内信号差、锁屏或切应用中断后的片段恢复，以及视频和 JSON 校验记录导出。系统清理网站存储后，离线壳和未导出的录像仍可能消失。

代驾车况记录应保留应用生成的完整水印成片与对应 JSON，避免只留聊天软件压缩后的副本。水印成片经过浏览器合成，不是未处理的相机原始码流；本机 SHA-256 匹配仅能核对文件与所选记录是否一致。设备时间、定位、车辆和订单文字可能被修改，本项目没有认证这些信息。发生争议时，按滴滴或受理机构当时的要求提交材料；如要求平台认可的取证工具或第三方存证，需另外接入指定服务。
